# Лабораторная работа №1. Архивация логов

## Описание

Bash-скрипт `log_rotate.sh` следит за заполнением файловой системы, на которой лежит каталог с логами. Если заполнение превышает заданный порог (по умолчанию 70 %), скрипт:

1. вычисляет, сколько байт нужно освободить, чтобы вернуться к порогу;
2. выбирает самые старые файлы каталога (по времени модификации), пока их суммарный размер не покроет нужный объём;
3. упаковывает выбранные файлы в архив в каталоге бэкапов;
4. проверяет, что архив читается;
5. только после успешной проверки удаляет исходные файлы;
6. пересчитывает заполнение и сообщает результат.

Дополнительно:

- **Максимальное сжатие (бонус).** Если установить переменную окружения `LAB1_MAX_COMPRESSION=1`, архив создаётся в формате `.tar.lzma`, иначе в `.tar.gz`.
- **Виртуальный диск.** В `lab1/virtual_disk/` лежат скрипты, которые создают и монтируют отдельный ext4-диск (loop-устройство) под каталог логов, чтобы безопасно проверять работу скрипта при реальном заполнении ФС.
- **Тесты.** В `lab1/tests/` лежит набор автотестов, который проверяет функции `log_rotate.sh` на временных файлах.

## Запуск основного скрипта

Все команды выполняются из каталога `lab1/`.

```bash
cd lab1
chmod +x log_rotate.sh
./log_rotate.sh -p LOG_DIR -b BACKUP_DIR [-x THRESHOLD]
```

### Параметры

| Флаг | Обязательный | Описание |
|------|--------------|----------|
| `-p LOG_DIR` | да | Каталог с лог-файлами. Обрабатываются только файлы верхнего уровня, подкаталоги не просматриваются |
| `-b BACKUP_DIR` | да | Каталог для архивов (создаётся, если его нет). Должен отличаться от `LOG_DIR` |
| `-x THRESHOLD` | нет | Максимально допустимое заполнение файловой системы в процентах, целое число от 1 до 100. По умолчанию `70` |
| `-h` | нет | Показать справку и выйти |

### Формат архива

Архивы создаются в `BACKUP_DIR` с именем `log_backup_<ГГГГММДД_ЧЧММСС>_<PID>_<RANDOM>.tar.gz`. При `LAB1_MAX_COMPRESSION=1` расширение будет `.tar.lzma`.

### Коды возврата

- `0`: ротация выполнена, ротация не требовалась или была показана справка (если после ротации заполнение всё ещё выше порога, скрипт выводит предупреждение, но завершается с кодом `0`);
- `1`: ошибка аргументов, каталогов, выбора файлов, создания или проверки архива, удаления файлов. Исходные файлы при этом не удаляются, пока архив не создан и не проверен.

### Примеры

```bash
# Порог по умолчанию (70 %)
./log_rotate.sh -p /var/log/myapp -b /backup/logs

# Свой порог и максимальное сжатие (.tar.lzma)
LAB1_MAX_COMPRESSION=1 ./log_rotate.sh -p /var/log/myapp -b /backup/logs -x 50
```

Важно: заполнение считается по **всей файловой системе**, на которой находится `LOG_DIR`. Если `BACKUP_DIR` лежит на той же файловой системе, архивы тоже занимают место, поэтому для реальной проверки бэкапы лучше хранить на другом разделе.

### Проверка на виртуальном диске

Чтобы безопасно проверить скрипт при реальном заполнении файловой системы, можно создать отдельный диск, смонтированный в `lab1/logs`:

```bash
cd lab1

# 1. Создать и смонтировать диск (размер в МБ, по умолчанию 2048)
./virtual_disk/setup_disk.sh 1024

# 2. Заполнить его тестовыми логами
for i in 1 2 3 4; do head -c 300M /dev/zero > "logs/app_$i.log"; done

# 3. Запустить ротацию (бэкапы вне виртуального диска)
./log_rotate.sh -p logs -b backup -x 50

# 4. Размонтировать диск и удалить образ и каталог logs
./virtual_disk/detach_disk.sh
```

`setup_disk.sh` и `detach_disk.sh` используют `sudo`. Перед удалением `detach_disk.sh` показывает список файлов в `logs/` и просит подтверждение (`y/N`).

## Запуск тестов

```bash
cd lab1
bash tests/test.sh
```

Тесты подключают `log_rotate.sh` как библиотеку функций, работают во временном каталоге и не требуют виртуального диска или `sudo`. Результат выводится в виде `PASS`/`FAIL` по каждому сценарию и итоговой строки `Passed: X/Y`. Код возврата `0` означает, что все тесты пройдены.

| Сценарий | Что проверяет |
|----------|---------------|
| `not_enough_space` | Если файлов не хватает для нужного объёма, `select_files` возвращает ошибку, архив не создаётся, файлы остаются на месте |
| `enough_space` | Выбираются нужные старые файлы, архив создаётся и проходит проверку, исходники удаляются, новейший файл сохраняется |
| `oldest_selected` | В архив попадают именно самые старые файлы |
| `invalid_args` | Несуществующий каталог и нечисловой объём приводят к ошибке с сообщением в stderr |
| `spaces_in_names` | Файлы с пробелами в именах обрабатываются корректно |
| `max_compression` | При `LAB1_MAX_COMPRESSION=1` создаётся корректный `.tar.lzma` |
| `full_scenario` | Полный цикл: проверка порога, выбор файлов, архивация, проверка и удаление, итоговое заполнение не выше порога |
